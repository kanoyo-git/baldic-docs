# Mixins: изменение поведения загруженного кода

Mixins принадлежат загрузчику Baldic и работают без необязательного пакета игрового API. Они позволяют выполнить код до или после метода, изменить его аргументы и результат либо преобразовать IL. Сначала проверьте, нет ли нужного события или готового метода в [BB+ API](../api-bbplus/README.md) и [BBCR API](../api-bbcr/README.md): публичный контракт обычно меньше зависит от внутреннего устройства игры.

В этой части книги используются собственные пространства имён `Baldic.Mixins` и `Baldic.Loader`. `0Harmony.dll` — имя совместимой сборки с низкоуровневым API Baldic; оно не означает, что в новых примерах требуется `using HarmonyLib`. Высокоуровневые средства `Mixin` находятся в `Baldic.Loader.dll`. Сборки загрузчика берутся из установленного SDK, а не вкладываются в каждый мод. Подготовка проекта описана в [инструментах разработки](../loader/tooling.md).

## Как выбрать уровень

| Задача | Средство | Что учитывать |
| --- | --- | --- |
| Изменить аргумент или результат известного метода | Типизированный Prefix/Postfix | Сигнатура callback связана с сигнатурой цели |
| Установить группу типизированных патчей с общим владельцем | `Mixin.CreatePatches` | Группа привязывается к `ModContext` |
| Описать патчи классами | `[Patch]` и `PatchAll` | Требуется явная установка группы/patcher |
| Обрабатывать разные цели через общий объект контекста | `Mixin.Inject`, `Replace`, `ModifyArg`, `ModifyReturn` | Используются `HookContext` и упакованные аргументы |
| Обернуть один вызов или изменить значение выражения | Типизированные операции | Число совпадений проверяется при установке |
| Выполнить произвольное преобразование IL метода | Собственный transpiler | Нужно сохранить стек, переходы и области исключений |
| Изменить доступность, поля, интерфейсы или наследование до загрузки | Access widener / early transformer | Это отдельная ранняя стадия, а не runtime-патч |

Типизированные патчи устанавливают исходные методы callback прямо в общий движок. Они не проходят через динамический `HookContext`. Такой путь подходит для часто вызываемого кода. Динамические hooks удобнее для общей обработки аргументов и конфигурационных условий, но создают объекты аргументов/контекста.

## Рекомендуемый путь чтения

Начните с [типизированных патчей](typed-patches.md): там показаны полный пример, `ref`, `out`, `__state`, владельцы и снятие патчей. Затем прочитайте [атрибуты](attributes.md) и [доступ к закрытым членам](reflection.md). Для точечных изменений тела метода перейдите к [компонуемым операциям](operations.md); [transpiler](transpilers.md) нужен, когда готовой операции недостаточно.

[Динамические hooks](dynamic-hooks.md) объясняют отдельную модель `HookContext` и декларативные `[Inject]`/`[Replace]`. Завершает раздел [совместимость](compatibility.md): взаимодействие владельцев, legacy-патчей, ограничения Mono и граница ранних преобразований. Точные сигнатуры собраны в [низкоуровневом справочнике](../reference/mixins-low-level.md) и [справочнике runtime Mixins](../reference/mixins-runtime.md).

Примеры используют маленькие учебные классы вместо конкретных классов игры. `NoInlining` в них делает цель наблюдаемой для демонстрации; оно не отключает встраивание методов игры. Подключайте собственный мод и его зависимости по правилам [пакетов](../loader/packages.md), устанавливайте runtime-патчи в подходящей [стадии жизненного цикла](../loader/lifecycle.md), а возвращённые регистрации сохраняйте, если требуется снять их раньше завершения контекста.
