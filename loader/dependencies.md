# Зависимости и вложенные библиотеки

Зависимость мода — контракт с другим пакетом или поставщиком окружения. Она определяет, можно ли активировать мод и какие пакеты должны пройти соответствующую стадию раньше него. Физическое присутствие DLL рядом с модом не заменяет запись в `depends`: загрузчик проверяет и управляемые ссылки между пакетами.

## Обязательная и рекомендованная связь

В `baldic.mod.json` отношения описываются объектами `ID: диапазон версии`:

```json
{
  "schemaVersion": 1,
  "id": "example-consumer",
  "version": "1.0.0",
  "depends": {
    "baldic": ">=1.0.0",
    "bbplus": "*",
    "example-library": "^1.2.0"
  },
  "recommends": { "example-ui": ">=1.0.0" },
  "breaks": { "incompatible-library": "<2.0.0" },
  "conflicts": { "alternative-ui": "*" },
  "entrypoints": { "init": ["Consumer.dll:Example.Mod"] }
}
```

`depends` — обязательное условие и ребро порядка загрузки. Отсутствующая, несовместимая или отказавшая обязательная зависимость блокирует потребителя. `breaks` тоже запрещает совместную активацию при совпавшем диапазоне. `recommends` сообщает о недостающей рекомендуемой версии, `conflicts` — о нежелательном сочетании; обе записи дают предупреждение и не равны жёсткому запрету.

Внешние поставщики включают загрузчик `baldic` и выбранную игру (`bbplus` или `bbcr`); окружение также учитывает внешние плагины. Не объявляйте собственный пакет с ID системного поставщика или API-модуля. Модули optional API имеют свои ID: например, ресурсы требуют `baldic-api-assets` в BB+ либо `baldic-api-bbcr-assets` в BBCR. Для [attachments](attachments.md) нужен CORE, а не только загрузчик.

## Реально поддерживаемые диапазоны

Версия пакета имеет форму SemVer `major.minor.patch`, с возможными prerelease и build metadata. В диапазоне можно указать точную версию (`1.2.3` или `=1.2.3`), сравнения, `*`, `1.*`/`1.x`, `1.2.*`/`1.2.x`, `~1.2.3`, `^1.2.3`. Условия через пробел объединяются как AND: `>=1.2.0 <2.0.0`. Ветви через `||` объединяются как OR.

`~1.2.3` ограничивает ту же major/minor, `^1.2.3` — тот же major. Для нулевой major реализация строже: `^0.2.3` оставляет minor 2, а `^0.0.3` не расширяет patch. Не переносите произвольный npm/NuGet-синтаксис по сходству: сокращённая голая версия `1.2`, интервалы с дефисом и операторы вне указанного набора не являются этим контрактом. Диапазоны сравнивают SemVer напрямую; отдельного npm-подобного правила исключения prerelease здесь нет.

`provides` задаёт массив дополнительных ID, которые предоставляет пакет. Зависимость по такому alias использует версию предоставляющего пакета. Alias не создаёт второй экземпляр библиотеки. Столкновение alias с реальным ID, окружением или другим alias считается ошибкой; `provides` не является способом незаметно заменить API-модуль.

## Выбор версии и порядок

При нескольких кандидатах загрузчик рассматривает версии по убыванию, ID — в ordinal-порядке, и возвращается к другим совместимым вариантам, если того требуют жёсткие связи, aliases, `breaks` или циклы. Результат не должен зависеть от порядка обхода каталогов. Разное содержимое на одинаковой старшей доступной версии остаётся неоднозначностью, а не разрешается случайным выбором файла.

Связанные компоненты решаются совместно; независимые компоненты не обязаны прекращать работу из-за чужой ошибки. Поиск ограничен 100 000 состояниями на компонент. При отсутствии полного решения применяется диагностика старших версий и изоляция ошибок; исчерпание лимита сопровождается предупреждением. Не используйте это как механизм намеренного перебора огромных наборов несовместимых библиотек.

После выбора версии обязательные зависимости упорядочиваются перед потребителями. Цикл `A → B → A` не имеет допустимого порядка и блокирует цикл и его зависимых потребителей. Записи `recommends`/`conflicts` не заменяют обязательную связь, если ваш `Init` уже обращается к библиотеке. Подробности стадий находятся в [жизненном цикле](lifecycle.md).

## Вложенная библиотека

Чтобы пользователь получил небольшую библиотеку вместе с модом, положите отдельный `.baldic` внутрь пакета и объявите его путь:

```json
{
  "schemaVersion": 1,
  "id": "example-consumer",
  "version": "1.0.0",
  "nestedDependencies": ["lib/example-library.baldic"],
  "depends": {
    "baldic": ">=1.0.0",
    "example-library": "^1.0.0"
  },
  "entrypoints": { "init": ["Consumer.dll:Example.Mod"] }
}
```

Сам архив `lib/example-library.baldic` содержит собственный корневой `baldic.mod.json` и файлы библиотеки. `nestedDependencies` делает ребёнка кандидатом; активирует подходящего ребёнка обязательная зависимость. Неиспользуемая библиотека не запускает entrypoints, mixins и early transformations и не загружает свои managed DLL.

Вложенность привязана к **выбранной версии** родителя. Отключённый родитель не поставляет кандидатов. Если несколько выбранных родителей несут одну версию с одинаковым содержимым, удаление одного носителя не мешает использовать другого. Отдельно установленная версия с тем же ID остаётся альтернативой при разрешении зависимостей. Game variant выбирается до раскрытия детей: BB+ не поставляет вложенные пакеты из ветви BBCR.

Выбранный вложенный пакет наследует активацию от родителя и не переключается самостоятельно в Mods. Для ID, существующего только как вложенный, отдельная enable-настройка не создаётся. Это также означает, что библиотека не должна строить свою пользовательскую модель на предположении о независимом переключателе.

## Пути и пределы

Пути деклараций используют `/`, остаются внутри пакета и оканчиваются `.baldic`. Запрещены абсолютные пути, `\`, drive prefixes, пустые сегменты, `.`/`..`, symlinks и повторные объявления. Поиск обрабатывает не больше восьми уровней вложенности, 128 деклараций архивов, 8192 ZIP entries и 512 МиБ суммарной распаковки; одна entry ограничена 128 МиБ. Использование кэша не отменяет эти бюджеты, повторное содержимое всё равно учитывается в декларациях и объёме.

`check` проверяет рекурсивно все объявленные дочерние архивы, включая неактивные и упакованные игровые ветви. Он валидирует содержимое, а не требует установленного окружения со всеми внешними зависимостями:

```sh
python3 tools/baldic.py check ./my-mod
python3 tools/baldic.py prepare-sdk ./my-mod \
  --dependency ./libraries/example-library.baldic \
  --managed "/path/to/game/BALDI_Data/Managed" \
  --output ./my-mod/.sdk
```

Подготовленный SDK использует выбранный игровой граф, применяет ранние преобразования активных зависимостей и экспортирует их DLL как локальные compile references. Собственные DLL потребителя не становятся его внешними зависимостями. `baldic-sdk.json` фиксирует выбранные версии, происхождение, fingerprints и хеши ссылок. При изменении библиотек пересоздайте SDK в новом каталоге; не копируйте полученные игровые DLL в выпуск мода.
